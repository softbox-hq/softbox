# Outreach

This note captures where and how to promote the project once the repository is public.

## Core Idea To Lead With

Do not position this as just another AI app builder.

Lead with:

- stable shell
- mutable inner app
- prompt -> build -> preview -> promote pipeline
- hosted standalone apps
- shell as runtime host, not just preview UI

Useful one-line framing:

- `AI-driven host runtime for mutable apps with build, preview, and live version swapping.`

Useful contrast line:

- `This is not another AI app builder. It is a host runtime for mutable apps.`

## Promotion Strategy

Do not post everywhere randomly.

Use this order:

1. public GitHub repo
2. short demo clip or GIF
3. short architecture/positioning post
4. targeted technical communities
5. direct outreach to a few high-signal people
6. broader social posts after that

## Outreach Circles

### 1. Core Technical Launch

Use these first:

- GitHub
- Show HN on Hacker News
- X / Twitter
- Reddit
- Lobsters

These reach technical builders quickly.

### 2. AI Coding / Tooling Circles

Show it to people already deep in:

- Codex
- Claude Code
- Cursor / Cline / OpenHands / OpenDevin type communities
- MCP and agent-tooling communities
- local-first AI tool communities

Why:

- they will understand the runtime distinction immediately

### 3. Open-Source Founder / Indie Builder Circles

Good targets:

- Indie Hackers
- OSS founder circles
- local-first communities
- product engineers who like devtools and infrastructure

Why:

- they may adopt, fork, or build on it

### 4. Frontend / Runtime Architecture Circles

Good targets:

- React communities
- Vite communities
- local app communities
- people interested in preview/deploy/runtime systems

Why:

- the hosted-runtime angle is interesting even without the AI layer

### 5. Thought-Piece Route

Do not rely only on repo links.

Write one short concept post such as:

- `The shell is the operating system, the app is the mutable program`
- `Why AI app builders are not the same as AI app runtimes`
- `From AI app builder to live app hosting runtime`

Why:

- ideas travel better through a sharp concept than a raw repository link

### 6. Direct Outreach

This matters more than broad posting.

Send a short note directly to:

- OSS maintainers in adjacent space
- AI coding tool people
- specific high-signal builder accounts
- people who already talk about Bolt, v0, Lovable, Dyad, Cursor, OpenHands

Format:

- one sentence of positioning
- repo link
- 30-60 second clip
- one reason this is different

### 7. Video Platforms

Have at least one short demo video:

- YouTube
- short clip attached to X posts
- maybe a README GIF for GitHub

Every other channel gets stronger if there is a clean video to point at.

### 8. Product Discovery Sites

Later, not first:

- Product Hunt
- BetaList
- devtool newsletters
- OSS newsletters

These are better after the idea is already sharpened.

## Best Audience

Do not optimize for general AI consumers first.

The best early audience is:

- AI coding tool builders
- runtime / infra tinkerers
- OSS devtool people
- indie hackers who understand prompt -> build -> swap workflows

## Messaging To Repeat

Repeat these ideas consistently:

- shell stays stable while the inner app changes
- hosted app behaves like a real app
- runtime promotes only healthy builds
- this is runtime architecture, not just app generation

## Minimal Launch Package

Before outreach, prepare:

- public GitHub repo
- strong README
- MIT license
- 30-90 second demo video or GIF
- one short explanation post
- one sentence positioning

## Suggested Sequence

1. publish repo
2. post demo clip on X
3. submit Show HN
4. post into selected Reddit / community channels
5. send direct outreach to a few relevant people
